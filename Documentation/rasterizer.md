# Rasterizer Overview

The Pipeline creates graphs (nodes and edges). The **Rasterizer** converts those graphs into physical, playable 2D environments. 

It assigns physical rooms to nodes, carves routes for edges, distributes user-defined entities like enemies and loot, and paints the final result onto a Godot `TileMapLayer`.

---

## 1. Prerequisites (The Semantic Connection)

To draw a level, the Rasterizer must know *what* to draw. This requires two things:

1.  **Semantic Tags:** Your graph nodes must be assigned semantic Types (e.g., `boss`, `treasure`, `corridor`). The Rasterizer uses these tags to determine room sizes, biome rules, and texture palettes. If your graph consists entirely of `empty` nodes, the Rasterizer will still work, but it will treat the entire map as one single default biome. Note that custom rules must be defined in order to differentiate between the biomes using the biome designer popup.
2.  **Visual Tile Mapping:** The Rasterizer needs visual graphics to paint. You must open the **Visual Tile Mapper** to load a spritesheet and assign specific pixel coordinates to your semantic tags. (See [Tile Mapping](tile-mapping.md)).

---

## 2. The Five Generation Layers

When you click **Rasterize Graph**, the `GraphRealizer` executes a strict, multi-pass sequence to build the map. You can selectively toggle these layers on or off in the UI for rapid testing.

1.  **Base Geometry:** 
    *   *Room Allocation:* Assigns physical rooms made out of tiles to every node. This can include custom made rooms. (See [Custom Room Designer](custom-rooms.md) for details).
    *   *Edge Routing:* Uses A* pathfinding (or orthogonal L-Paths) to carve contiguous walkable corridors between rooms.
    *   *Cellular Smoothing & Erosion:* Chips away blocky grid corners to make the environment look organic.
    *   *Walls:* Wraps the entire walkable floorplan in solid collision walls.
2.  **Progression:** 
    *   The `ProgressionSolver` analyzes the physical topology to find dead-ends, calculate depth, and intelligently distribute locked doors, required keys, and optional vaults. (See [Lock-and-Key Progression](progression.md)).
3.  **Structures:** 
    *   Scans the biome configuration and places large, multi-tile custom geometry (like boss altars or statues) directly onto the grid, ensuring they don't block critical paths. (See [Structures & Scatter](structures-scatter.md)).
4.  **Entities:** 
    *   Populates the remaining valid floor space with 1x1 entities (scatter, loot, enemies), followed by the placement of invisible Temporal Triggers.
5.  **Textures (WFC):** 
    *   Runs the Wave Function Collapse algorithm over the finalized geometry to blend distinct biomes together and paint complex organic textures (like winding rivers or dirt paths). (See [WFC Texturing](wfc.md)).

## 3. The Validation VCR & Analytics Report

The instant a map finishes rasterizing, a background thread fires up the **Generation Validator**.

The Validator flood-fills the map starting from the Player Spawn tile. It tests if the map is actually solvable by simulating a playthrough: picking up keys, unlocking doors, and navigating corridors.

### The Timeline Tab (VCR)
This tab records snapshots of every step during the Rasterization process. If your map looks broken, you can scrub through the timeline to pinpoint exactly which layer (e.g., Cellular Smoothing vs WFC) caused the issue. It also displays microsecond execution times, helping you identify performance bottlenecks.

### The Report Tab
A comprehensive analytics dashboard generated by the Validator. It highlights:
*   **Playability:** Was the exit reached?
*   **Coverage:** Did the algorithm leave unreachable "island" rooms?
*   **Diagnostics:** Lists any failed A* corridors, rejected custom rooms (due to overlapping), or WFC contradictions.

*(For a deep dive into the Validator controls and Oracle settings, see [Validator & Player Simulation](validator.md)).*

## 4. Dynamic Regeneration (The Dirty Rect)

The Rasterizer supports **Partial Regeneration**. You do not have to wipe the entire TileMap to see a change.

If you select a node or edge in the Graph Editor and click **Regenerate Selection**, the engine calculates a **"Dirty Rect"**—the exact physical bounding box encompassing that node and its immediate neighbors. 

It wipes only the tiles inside the Dirty Rect, recalculates the geometry for that localized area, and seamlessly stitches the new layout back into the surrounding permanent grid.

*   **Preview Affected Tiles:** Use this button to visualize the exact blast radius of a dynamic regeneration before committing to it.
*   **Temporal Triggers:** This Dirty Rect system is the exact same engine used by Temporal Triggers during gameplay to dynamically shift the dungeon around the player. (See [Triggers & Temporal Progression](triggers.md)).
