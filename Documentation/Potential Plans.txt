# Procedural Graph Editor - Architecture & Roadmap

## Current Engine State
- **Semantic Registry:** A unified data structure handling customized semantic types and properties across four distinct targets: `NODE`, `EDGE`, `AGENT`, and `ZONE`.
- **Universal Undo/Redo:** The `GraphHistory` and `CmdBatch` systems faithfully record data mutations across all targets, utilizing deep copies (`.duplicate(true)`) to prevent reference mutations.
- **Contextual Hit Detection & UI:** Tools share base hit-detection logic. The editor provides live, contextual hover-glow feedback depending on which semantic object the active tool targets. Omni-box selection allows grabbing multiple targets concurrently.
- **Agent Capabilities:** `AgentWalker` operates via a Capability/Brain architecture. The `CapPainter` allows agents to procedurally alter node types, edge weights, and custom properties as they traverse the graph.

## Future Development Paths

### 1. Force-Directed Layout (Buoyancy / Physics)
**Goal:** Automatically untangle messy procedurally generated graphs.
**Implementation:** Implement a Fruchterman-Reingold style physics step. Nodes act as repelling magnets (Coulomb's law); Edges act as attracting springs (Hooke's law). 
**UI:** Driven by a continuous "Buoyancy Mode" toggle in the top menu bar, allowing the user to watch the graph organically untangle in real-time.

### 2. Directed Acyclic Graphs (DAG) & Questlines
**Goal:** Introduce logical constraint solving to represent progression systems, tech trees, or narrative questlines.
**Implementation:** Create a `StrategyQuestGen` that enforces acyclic flows. Agents or generators will flag nodes with semantic data (e.g., `required_item`, `boss_encounter`) and dynamically update edge `lock_level` properties to ensure a mathematically solvable progression puzzle.

### 3. Advanced Agent Graph Rewriting
**Goal:** Evolve agents from passive painters to active architects.
**Implementation:** Introduce cross-agent interactions and semantic-reading brains. Agents standing on the same node can trade data, merge nodes, sever edges, or spawn new branches based on the semantic properties of the zone they are currently occupying.

## Phase 1 – Safe Command API on `GraphEditor`

These are foundational. They create the safe, undoable mutation paths that all inspectors and controllers will later use. No existing functionality is altered.

| # | Task | Severity | Ease | Problem & Concern |
|---|------|----------|------|-------------------|
| 1.1 | **Make `set_node_position` undoable** | Critical | Easy | Currently, when `is_preview = false` it writes directly to the graph without a command. The inspector uses it for X/Y fields – every typed position change is permanent. **Without this, node moves via the inspector cannot be undone.** |
| 1.2 | **Add `set_agent_property(agent, key, value)`** | Critical | Easy | No public method exists to change an agent’s properties through a command. Inspectors and controllers all call `agent.apply_setting()` directly, bypassing undo. **All agent edits are currently permanent.** |
| 1.3 | **Add `set_zone_property(zone, key, value)`** | Critical | Easy | Same as agent – zones are mutated directly via `zone.set()` or `zone.custom_data[key] = value`. **Zone type changes, traversal costs, etc. cannot be undone.** |
| 1.4 | **Add `get_agents()` and `get_zones()` safe accessors** | Medium | Trivial | Controllers access `graph_editor.graph.agents` and `.zones` directly. If the internal storage format changes (e.g., to a dictionary), those controllers break. **Encapsulation leak – future-proofing only.** |
| 1.5 | **Add `request_redraw()` wrapper** | Medium | Trivial | Many controllers call `graph_editor.renderer.queue_redraw()` directly. This exposes the renderer as a public dependency. **Prevents us from changing or replacing the renderer later.** |
| 1.6 | **Add `clear_current_path()` wrapper** | Low | Trivial | `AgentController` directly clears `graph_editor.current_path` and the renderer’s `current_path_ref` array. **Encapsulation; minor risk of future inconsistency.** |
| 1.7 | **Add `set_debug_depth(enabled)` wrapper** | Low | Trivial | `StrategyController` toggles `graph_editor.renderer.debug_show_depth` directly. **Same encapsulation issue.** |

## Phase 2 – Canonical Edge Store

This refactoring removes the dual-storage of edges (`NodeData.connections` + `Graph.edge_data`), which is the root cause of asymmetric-weight bugs, fragile mirroring, and future data corruption.

| # | Task | Severity | Ease | Problem & Concern |
|---|------|----------|------|-------------------|
| 2.1 | **Create `EdgeData` class** | Critical | Easy | No unified record exists for an edge. Currently, weight and direction are stored twice for undirected edges, and properties can silently desync. **This is the data structure that fixes the core model.** |
| 2.2 | **Add `_canonical_key` helper to `Graph`** | Critical | Trivial | All edge lookups currently use raw, order-dependent keys. **Without a canonical key, we cannot store an undirected edge once.** |
| 2.3 | **Add `edge_store` dictionary and cache dirty flag to `Graph`** | Critical | Trivial | The new store will hold the single canonical record per edge. **Needed alongside the old storage until migration is complete.** |
| 2.4 | **Update `add_edge` to write to `edge_store`** | Critical | Moderate | The existing `add_edge` only touches legacy stores. The new store must be kept in sync now so that when we later switch readers, the data is already present. **We’ve already written this code.** |
| 2.5 | **Update `remove_edge` to update `edge_store`** | Critical | Moderate | Same as above – must handle direction removal correctly (e.g., removing one direction from a bi‑directional edge leaves the other). **Necessary before we can switch readers.** |
| 2.6 | **Rewrite `has_edge`, `get_edge_weight`, `get_edge_data`, `set_edge_weight`, `get_neighbors` to use `edge_store`** | Critical | Moderate | These are the consumers. They must read from the new store, and the neighbor cache must be rebuilt on demand. **This is the point where legacy storage stops being the primary source of truth.** |
| 2.7 | **Update `GraphRenderer._draw_layer_edges` to use `edge_store`** | Critical | Moderate | Currently the renderer deduplicates bidirectional edges manually and infers direction from `has_edge`. With a canonical store, drawing becomes simpler and is no longer dependent on fragile legacy checks. **Eliminates drawing bugs when direction/weight desyncs.** |
| 2.8 | **Update edge commands (`CmdConnect`, `CmdDisconnect`, `CmdSetEdgeWeight`, `CmdSetEdgeDirection`)** | Critical | Moderate | These must use the new `Graph` API exclusively. `CmdDisconnect` currently snapshots and merges two copies – this becomes a single snapshot. **The commands are where undo integrity for edges lives.** |
| 2.9 | **Add `post_load_fixup` migration: build `edge_store` from legacy data** | High | Moderate | Existing save files contain the old dual storage. On load, we must reconstruct the canonical store from `edge_data` so the graph is immediately compatible with the new readers. **Without this, loading old files breaks.** |
| 2.10 | **Remove `NodeData.connections` and `Graph.edge_data`** | High | Easy | Once all readers and writers are migrated, the old storage is dead weight and a trap for future code. **Cleanup; prevents accidental usage of the old system.** |
| 2.11 | **Remove manual mirroring in `InspectorEdge`** | Critical | Easy | The inspector currently writes properties to both `A→B` and `B→A`. With a canonical record, this is unnecessary and will overwrite values incorrectly. **Part of the inspector refactor; can be done after 2.6.** |

## Phase 3 – Inspector Refactoring

All inspectors currently mutate the model directly, bypassing commands. Phase 3 routes every change through the new, safe API created in Phase 1.

| # | Task | Severity | Ease | Problem & Concern |
|---|------|----------|------|-------------------|
| 3.1 | **Fix `InspectorNode` positioning to use undoable `set_node_position`** | Critical | Trivial | The inspector calls `graph_editor.set_node_position` which was non‑undoable. After Phase 1, the same call now pushes a command. **No code change needed beyond ensuring the new method is in place.** |
| 3.2 | **Fix `InspectorNode` physics property read/write** | High | Easy | Physics properties (`physics_repulsion`, `physics_mode`) are read from `custom_data` but may be written to the hardcoded `NodeData.physics_repulsion` variable by `CmdSetProperty`. This causes a read/write mismatch. **Move all physics properties to `custom_data` and remove hardcoded field, or unify read path.** |
| 3.3 | **Fix `InspectorNode` mixed‑state detection for physics** | Medium | Easy | The mixed‑state checker only looks at `custom_data`, missing hardcoded physics fields. **Leads to incorrect “(mixed)” display.** |
| 3.4 | **Batch bulk custom property changes in `InspectorNode`** | Medium | Easy | When multiple nodes are selected, changing a custom property creates one undo entry per node. **Users must press Undo once per node – poor UX for bulk edits.** |
| 3.5 | **Refactor `InspectorEdge` to use canonical edge store** | Critical | Easy | After Phase 2, edge properties exist in one place. The inspector must read/write that single record and remove all manual mirroring. **The current mirroring code will break after the edge store migration.** |
| 3.6 | **Refactor `InspectorAgent` to use `set_agent_property`** | Critical | Easy | Replace all `agent.apply_setting()` calls with `graph_editor.set_agent_property(agent, key, value)`. **This single change makes all agent edits undoable.** |
| 3.7 | **Refactor `InspectorAgent` mixed‑state detection** | Medium | Easy | The detection function uses `_get_agent_value` which returns `null` for custom‑only keys, breaking mixed detection. **Unify reading to always check `custom_data`.** |
| 3.8 | **Refactor `InspectorZone` to use `set_zone_property`** | Critical | Easy | Replace all `zone.set()` and `zone.custom_data[key] = value` with `graph_editor.set_zone_property(zone, key, value)`. **All zone edits become undoable.** |
| 3.9 | **Fix `InspectorController._on_purge_requested` to use commands** | Critical | Easy | The purge function directly deletes keys from `custom_data` and `edge_data`. **No undo, no dirty flag, and on edges it only deletes one copy – leaving the other stale.** |
| 3.10 | **Remove all direct `graph_editor.mark_modified()` calls from inspectors** | Medium | Easy | After migration, the command pipeline automatically marks the graph modified. **Redundant calls can mask bugs and should be removed.** |

## Phase 4 – Controller Refactoring

Controllers also mutate the graph directly or access internal state. Phase 4 routes them through the same safe API.

| # | Task | Severity | Ease | Problem & Concern |
|---|------|----------|------|-------------------|
| 4.1 | **Fix `ZoneController` zone type and lock toggles to use commands** | High | Easy | Zone type (`zone_type`) and group toggle (`is_grouped`) are set directly on the zone object. **Cannot be undone; can fundamentally alter engine behaviour.** |
| 4.2 | **Remove direct renderer access from `ZoneController`** | Medium | Easy | Calls `graph_editor.renderer.queue_redraw()` directly. **Use `request_redraw()` instead.** |
| 4.3 | **Replace `graph_editor.graph.zones` access with `get_zones()`** | Medium | Trivial | Direct array access breaks if internal storage changes. **Encapsulation.** |
| 4.4 | **Fix `AgentController` behavior changes to use `set_agent_property`** | Critical | Easy | All agent edits via the behaviour panel call `agent.apply_setting()` directly. **Every behaviour, algorithm, and target node change is un‑undoable.** |
| 4.5 | **Wrap `AgentController`’s “Clear Agents” in a single undo transaction** | Medium | Trivial | Each agent removal creates its own undo step. **Clearing 50 agents requires 50 undos – terrible UX.** |
| 4.6 | **Remove direct renderer and graph access from `AgentController`** | Medium | Easy | It pokes `graph_editor.renderer.current_path_ref`, `graph_editor.current_path`, and `graph_editor.graph.agents`. **Use new wrappers and accessors.** |
| 4.7 | **Fix `StrategyController` “Clear Agents” to batch undo** | Medium | Trivial | Same flooding problem as AgentController. **Wrap in transaction.** |
| 4.8 | **Remove direct renderer access from `StrategyController`** | Low | Trivial | `graph_editor.renderer.debug_show_depth` is set directly. **Use `set_debug_depth()`.** |
