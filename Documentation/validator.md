# Validator & Player Simulation

Because procedural generation is highly randomized, mathematical errors or overlapping structures can accidentally create "softlocks" (unbeatable maps), the **Generation Validator** ensures every single map generated by the tool is 100% playable, warning you in the report otherwise if unbeatable.

It operates as a headless player simulation that spawns at the Start Point and flood-fills the walkable tiles of the map.

---

## 1. Simulation Mechanics

The Validator physically navigates the grid using a Breadth-First Search. As it expands, it visually paints the map with a translucent colored puddle, while the current "frontier" of exploration glows cyan.

*   **Keys & Inventory:** When the puddle touches a Key entity, it picks it up and adds it to its internal inventory memory.
*   **Doors:** When the puddle touches a Locked Door, it halts. It checks its inventory memory. If it has the matching key, it unlocks the door and continues pouring through. If it doesn't, it logs the door as "stuck."
*   **Exit:** If the puddle touches the Dungeon Exit entity, the map is marked as **Playable**.

---

## 2. Validation Settings

In the **Validator** tab, you can customize how the simulation behaves using the VCR controls.

### Exhaustive Exploration (Delay Doors)
By default, the Validator unlocks a door the instant it touches it (if it has the key). 
If you enable **Delay Doors**, the Validator refuses to open any doors until it has explored 100% of the currently accessible area. This proves that the player isn't forced to backtrack unnecessarily and simulates a "completionist" playstyle.

### Temporal Trigger Handling
Determines what the Validator does when it steps on a Temporal Trigger.
*   **Warn & Pause:** Halts the simulation and asks you for permission to regenerate the map.
*   **Auto-Accept:** Instantly fires the trigger, regenerates the map, and continues the simulation.
*   **Ignore:** The Validator walks over the trigger without activating it (useful for testing the base layout).

---

## 3. The Regeneration (Amnesia)

If you hit a Temporal Trigger (or click 'Regenerate Selection') while the Validator is running, the grid literally changes underneath it. 

The Validator handles the regeneration mathematically:
1.  It compares its explored puddle to the new physical grid.
2.  Any puddle tiles that were turned into solid walls by the regeneration are "evaporated."
3.  If the evaporation cuts the Validator off from the Start Point, it triggers the **Amnesia**: It forgets its puddle, drops a new starting pin at its exact current coordinate, and begins exploring again—but it keeps all the Keys it found in its inventory. 

This proves that even if the dungeon shifts around the player, they can still beat the game.
